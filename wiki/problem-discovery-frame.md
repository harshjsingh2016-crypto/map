# Problem discovery frame

A fixed structure for working a problem before committing to a solution. Four regions,
read left to right: the **starting point** (the current position and situation, stated
plainly), the **goal** (the solution as an end state), and between them the **paths** —
candidate routes from one to the other. **Constraints** sit below the whole frame and
apply to every path.

The frame's claim is that a solution is not a thing you write down; it is a path you
choose. Paths are compared, one is picked, and only then are **tasks** extracted — the
concrete work is a derivative of the chosen path, not a brainstormed list of its own.
Constraints do the filtering: a hard constraint kills a path outright, a soft one only
costs it points in the comparison.

The frame is deliberately empty at birth — regions first, values second — so that the
shape of the reasoning is settled before any specific problem is poured into it.
