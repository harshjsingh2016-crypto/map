# Codex control loop

Reality is a stream of events across time, place and the people, machines and nature that cause them. A moment passes and its events freeze as the past. The now is the only place anything can be caused. The future is endless possibility, and the events that actually occur now decide which possibility becomes real. That is the vector: the direction of reality, changing course on what happens in the moment.

Codex is the system built on that reading. Every goal, in mind, body, money, relationships or work, is a future state, and the only lever on it is the events orchestrated now, by oneself or through others. So the system has four jobs: record what occurred and distil what it teaches, keep the desired future clear enough to recognise when it arrives, say what must be done today, and keep the mind on that list until the end of the day.

The refinement settled while defining it: there is not one vector. Five domains share one budget of hours, and hours are the only resource that moves linearly and cannot be stored. The real decision the system makes each morning is where the hours go, not what could be done. And most events are not caused by the operator at all, so every planned event carries a tag, self, via someone, or outside, and lessons are drawn only from the first two.

In practice it is seven files and four skills. A horizon file holds the desired future per domain with a signal that proves it arrived. A path file holds the events that must occur between now and each horizon, planned backward from the signal. A now file holds today's actions, at most three, and is the only file open during the day. The ledger holds one file per day of what was done, what happened, what was noticed and the hours spent. Lessons are hypotheses drawn from the ledger, each with a confidence word. The budget file holds the hours a week that are the operator's to direct. The loop runs as a morning skill that writes the now file, an evening skill that appends the ledger and checks the day's list, a weekly review that turns ledger into lessons and replans the path, and a quarterly interview that revisits the horizon.

It is the Autonomous Ops Ladder applied to the operator: the ledger is L1 visibility, the done-or-not check on each action is L2 accountability, the morning list is L3 recommendation, the path is L4 strategy, and L5, the system orchestrating others, is named and not built.

The constraint that shaped the build: the loop must run from a phone. Everything it needs lives inside the repo, and every skill pulls first and commits last, so a session on the desktop and a session on the mobile app never drift by more than one run.
